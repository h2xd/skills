# Page types

Generated by `node scripts/to-page.ts spec --md`. Do not edit by hand.

## checklist

```
Checklist {t: "checklist", id, title, intro, items: Item[], base?, facts?: string[]}
Item {id, title, text, q?, opts?: Opt[], rec?, preselect?: boolean, block?, where?: Where[], note?}
Where [path, hint?]
Opt [id, label, reason?], or a bare string that is its own id and label

Rules:
- Item ids are unique. Option ids are unique per item.
- q and opts come together. rec names an option id. preselect needs rec.
- Text fields accept `code`, **bold**, [link](url) and \n. Never write HTML.
- An unknown field is an error. JSON keeps only the last of two equal keys, so never repeat a key.

Example:
{"t":"checklist","id":"example-release-check","title":"Release check · Example shop","intro":"Open each page, check the item and write a note.","base":"http://localhost:8080","facts":["Language switch: `?lang=en`"],"items":[
 {"id":"C1","title":"Product grid at small widths","text":"The grid now uses 2 columns below 640 px. Check that the cards do not overflow.","q":"Is 2 columns OK on small phones?","opts":["OK","Back to 1 column"],"block":"ProductGrid","where":[["/products","375 px: scroll to the end"],["/sale","375 px"]],"note":"The sale page has fewer products in the test data."},
 {"id":"C2","title":"Footer links on wide screens","text":"The footer links stop at the content width now.","q":"Keep, or full width?","opts":["Keep","Full width"],"where":[["/","1440 px"]]}
]}
```

## grilling

```
Grilling {t: "grilling", id, title, intro, items: Q[], previous?, from?, to?, purpose?, deadline?}
Q {id, prio: "blocker"|"important"|"nice", q, why, opts: Opt[], rec?, preselect?: boolean, refs?: string[], depends?: string[]}
Opt [id, label, reason?], or a bare string that is its own id and label

Rules:
- Item ids are unique across the whole round chain. Option ids are unique per item.
- rec names an option id. preselect needs rec. Option ids "dunno" and "other" are taken: the page adds "I don't know" and "Something else".
- Round 2 and later set previous to the earlier file name without ".form.json", such as "round-1". depends names ids from this round or an earlier one.
- Text fields accept `code`, **bold**, [link](url) and \n. Never write HTML.
- An unknown field is an error. JSON keeps only the last of two equal keys, so never repeat a key.

Example:
{"t":"grilling","id":"example-export","title":"CSV export · Round 1","intro":"Pick an option per question. The first decisions block the build.","from":"The export team","to":"Product owner","purpose":"Settle the export design before the first ticket.","deadline":"Friday","items":[
 {"id":"Q1","prio":"blocker","q":"Where does the export run?","why":"It decides if a large export can block the request.","opts":[["a","In the request"],["b","In a background job","Large exports take longer than the 30 s request timeout."]],"rec":"b","refs":["src/export/run-export.ts:42"]},
 {"id":"Q2","prio":"blocker","q":"Who may export?","why":"The export contains customer emails.","opts":[["admin","Admins only","Smallest data exposure."],["team","Every team member"]],"rec":"admin"}
]}
```

## questionnaire

```
Questionnaire {t: "questionnaire", id, title, intro, to, purpose, items: Ask[], previous?, from?, deadline?, minutes?, context?}
Ask {id, q, theme?, why?, opts?: Opt[], rec?, preselect?: boolean, guess?}
Opt [id, label, reason?], or a bare string that is its own id and label

Rules:
- Item ids are unique across the whole round chain, and "more" is taken: the page ends with "Anything else?".
- An item without opts is an open question. guess is our best guess for the reader to correct, only on an open question.
- rec names an option id, and the page shows it first. preselect needs rec. Option ids are unique per item, and "dunno" and "other" are taken.
- An item with a new theme starts a heading. The items after it without a theme stay under that heading.
- Round 2 and later set previous to the earlier file name without ".form.json", such as "round-1".
- Text fields accept `code`, **bold**, [link](url) and \n. Never write HTML.
- An unknown field is an error. JSON keeps only the last of two equal keys, so never repeat a key.

Example:
{"t":"questionnaire","id":"example-onboarding","title":"Your team's onboarding","intro":"We are building the new onboarding for your team. Your answers decide what we build first.","from":"The product team","to":"Head of customer success","purpose":"Plan the first release of the onboarding.","deadline":"Friday, 14 November","minutes":"10","context":"Today a new user gets one welcome email and a link to the help center. **About half** of new users never finish their profile.","items":[
 {"id":"Q1","theme":"Your new users","q":"Who sets up a new account at your company?","opts":[["admin","An admin, for the whole team","One person sets up many accounts."],["self","Each person, for themselves"]],"rec":"self"},
 {"id":"Q2","q":"Where do new users get stuck today?","why":"We want to fix the step that costs the most, not the step we can see.","guess":"At the step that connects the calendar. Most support tickets are about it."}
]}
```
