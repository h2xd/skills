# Page types

Generated by `node scripts/to-page.ts spec --md`. Do not edit by hand.

## checklist

```
Checklist {t: "checklist", id, title, intro, items: Item[], summary?: string[], base?, facts?: string[]}
Item {id, title, text, q?, opts?: Opt[], rec?, preselect?: boolean, block?, where?: Where[], note?}
Where [path, hint?]
Opt [id, label, reason?], or a bare string that is its own id and label

Rules:
- Item ids are unique. Option ids are unique per item.
- q and opts come together. rec names an option id. preselect needs rec.
- The title names the topic only. The page shows the type and the round above it.
- Write a summary on every page: 1 to 5 short bullets on what is at stake, what is settled and what this page asks.
- Text fields accept `code`, **bold**, [link](url) and \n. Never write HTML.
- An unknown field is an error. JSON keeps only the last of two equal keys, so never repeat a key.

Example:
{"t":"checklist","id":"example-release-check","title":"Release check · Example shop","intro":"Open each page, check the item and write a note.","summary":["Release 2.4 changes 15 parts of the shop.","Tick each item. A no blocks the release."],"base":"http://localhost:8080","facts":["Language switch: `?lang=en`"],"items":[
 {"id":"C1","title":"Product grid at small widths","text":"The grid now uses 2 columns below 640 px. Check that the cards do not overflow.","q":"Is 2 columns OK on small phones?","opts":["OK","Back to 1 column"],"block":"ProductGrid","where":[["/products","375 px: scroll to the end"],["/sale","375 px"]],"note":"The sale page has fewer products in the test data."},
 {"id":"C2","title":"Footer links on wide screens","text":"The footer links stop at the content width now.","q":"Keep, or full width?","opts":["Keep","Full width"],"where":[["/","1440 px"]]}
]}
```

## grilling

```
Grilling {t: "grilling", id, title, intro, items: Q[], summary?: string[], previous?, from?, to?, purpose?, deadline?}
Q {id, prio: "blocker"|"important"|"nice", q, why, opts: Opt[], rec?, preselect?: boolean, refs?: string[], depends?: string[]}
Opt [id, label, reason?], or a bare string that is its own id and label

Rules:
- Item ids are unique across the whole round chain. Option ids are unique per item.
- rec names an option id. preselect needs rec. Option ids "dunno" and "other" are taken: the page adds "I don't know" and "Something else".
- Round 2 and later set previous to the earlier file name without ".form.json", such as "round-1". depends names ids from this round or an earlier one.
- The title names the topic only. The page shows the type and the round above it.
- Write a summary on every page: 1 to 5 short bullets on what is at stake, what is settled and what this page asks.
- Text fields accept `code`, **bold**, [link](url) and \n. Never write HTML.
- An unknown field is an error. JSON keeps only the last of two equal keys, so never repeat a key.

Example:
{"t":"grilling","id":"example-export","title":"CSV export","intro":"Pick an option per question. The first decisions block the build.","summary":["Customers want their orders as a file.","Nothing is settled yet.","Two blockers decide where the export runs and who may use it."],"from":"The export team","to":"Product owner","purpose":"Settle the export design before the first ticket.","deadline":"Friday","items":[
 {"id":"Q1","prio":"blocker","q":"Where does the export run?","why":"It decides if a large export can block the request.","opts":[["a","In the request"],["b","In a background job","Large exports take longer than the 30 s request timeout."]],"rec":"b","refs":["src/export/run-export.ts:42"]},

]}
```

## questionnaire

```
Questionnaire {t: "questionnaire", id, title, intro, to, purpose, items: Ask[], summary?: string[], previous?, from?, deadline?, minutes?, context?}
Ask {id, q, theme?, why?, opts?: Opt[], rec?, preselect?: boolean, guess?}
Opt [id, label, reason?], or a bare string that is its own id and label

Rules:
- Item ids are unique across the whole round chain, and "more" is taken: the page ends with "Anything else?".
- An item without opts is an open question. guess is our best guess for the reader to correct, only on an open question.
- rec names an option id, and the page shows it first. preselect needs rec. Option ids are unique per item, and "dunno" and "other" are taken.
- An item with a new theme starts a heading. The items after it without a theme stay under that heading.
- Round 2 and later set previous to the earlier file name without ".form.json", such as "round-1".
- The title names the topic only. The page shows the type and the round above it.
- Write a summary on every page: 1 to 5 short bullets on what is at stake, what is settled and what this page asks.
- Text fields accept `code`, **bold**, [link](url) and \n. Never write HTML.
- An unknown field is an error. JSON keeps only the last of two equal keys, so never repeat a key.

Example:
{"t":"questionnaire","id":"example-onboarding","title":"Your team's onboarding","intro":"We are building the new onboarding for your team. Your answers decide what we build first.","summary":["New users get one email today, and many stop in week one.","Your answers set what the first release builds."],"from":"The product team","to":"Head of customer success","purpose":"Plan the first release of the onboarding.","deadline":"Friday, 14 November","minutes":"10","context":"Today a new user gets one welcome email and a link to the help center. **About half** of new users never finish their profile.","items":[
 {"id":"Q1","theme":"Your new users","q":"Who sets up a new account at your company?","opts":[["admin","An admin, for the whole team","One person sets up many accounts."],["self","Each person, for themselves"]],"rec":"self"},
 {"id":"Q2","q":"Where do new users get stuck today?","why":"We want to fix the step that costs the most, not the step we can see.","guess":"At the step that connects the calendar. Most support tickets are about it."}
]}
```

## decision

```
Decision {t: "decision", id, title, intro, items: Choice[], summary?: string[], from?, to?, purpose?, deadline?}
Choice {id, q, context, drivers: string[], options: Considered[], rec?, reason?, multi?: boolean}
Considered {id, label, scores: 1..5[], good?: string[], bad?: string[]}

Rules:
- One decision per page, in one round. Ask follow-up questions in a grilling round.
- drivers are the criteria. Each option has one score per driver, in the same order: 1 is poor, 5 is strong.
- rec names an option id, and reason says why. multi: true lets the reader pick several options. Option ids are unique, and "dunno" and "other" are taken.
- The title names the topic only. The page shows the type and the round above it.
- Write a summary on every page: 1 to 5 short bullets on what is at stake, what is settled and what this page asks.
- Text fields accept `code`, **bold**, [link](url) and \n. Never write HTML.
- An unknown field is an error. JSON keeps only the last of two equal keys, so never repeat a key.

Example:
{"t":"decision","id":"example-export-runner","title":"CSV export runner","intro":"Pick where the export runs. The table rates each option on each driver.","summary":["Large exports take longer than the 30 s request timeout.","Who may export is settled: admins only.","This page decides where the export runs."],"items":[
 {"id":"D1","q":"Where does the CSV export run?","context":"An export of 50 k orders takes about 90 s. The request timeout is 30 s.","drivers":["Large exports","Effort","Running cost"],"options":[{"id":"request","label":"In the request","scores":[1,5,5],"good":["No new parts"],"bad":["Fails above about 15 k orders"]},{"id":"job","label":"In a background job","scores":[5,3,4],"good":["Uses the job runner we have"],"bad":["Needs a way to hand the file back"]},{"id":"service","label":"In a separate export service","scores":[5,1,2],"bad":["A new service to deploy and watch"]}],"rec":"job","reason":"Handles every size with the runner we already operate."}
]}
```
