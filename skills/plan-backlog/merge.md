# Merge brief

You merge the issues that the user approved, set the labels and write
proposals. Read `docs/agents/issue-tracker.md` first for the operations and the
label strings. Post every comment per `skills/setup-tone/github-text.md`.

## Input

- `issues.json`: every open issue with its body and comments.
- `decisions.json`: for each approved group, the survivor, the members and the
  label choice.
- A scratchpad directory for drafts and `proposals.md`.

## 1. Rewrite each survivor

For each group in `decisions.json`:

1. Copy the survivor's body to a draft file.
2. Add a `## Joined from #<n>` section for each member: its rule or scope in
   short bullets, the acceptance criteria it added, and its evidence in a
   `<details>` block. Keep every fact. Cut only repeated words.
3. End the draft with `Replaces #<n>, #<m>.`
4. Write a title that covers the whole scope.
5. Edit the survivor with
   `gh issue edit <n> --title "<title>" --body-file <file>`.

## 2. Close the members

For each member, run **Comment** with:

```
> *This was generated by AI during backlog grooming.*

Merged into #<survivor>. The full text is in that issue.
```

Then close it with `gh issue close <n> --reason "not planned"`.

## 3. Set the labels

The label strings come from the `## Triage` section of the tracker page.
Use the **Label** operation to set them.

- **Category.** `bug` when any member is a bug. Otherwise `enhancement`.
- **State.** `ready-for-agent` when the survivor has acceptance criteria, or the
  user chose it for the group. Otherwise `needs-triage`.
- Remove the old state, so the survivor has exactly one category and one state.
- Also label every open issue outside a group that has no label, by the same
  rule. Leave `idea` issues alone.

## 4. Check

Run **View** on each survivor. Make sure the title, the labels and the
`Replaces` line are present, and each member is closed.

## 5. Propose

Write `proposals.md`, one line for each open issue that needs more work:

- A survivor with more than five items. Propose a split by topic.
- An issue with no acceptance criteria. Propose `h2xd:plan-triage`.
- An issue that names code that exists already. Propose a close.
- An issue that waits on another open issue. Propose a blocking edge.
- An issue whose shape is open. Propose `h2xd:plan-grill`.
- A rule in the tracker page that the issues break, such as a wrong label.

Give each line the issue number, the finding and the next skill.
Change nothing for a proposal.

## Return

The path of `proposals.md` and one line for each group:
`🟢 #<survivor>: merged #<n>, #<m>` or `🔴 #<survivor>: <what failed>`.
