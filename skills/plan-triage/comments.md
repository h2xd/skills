# Triage comments

Every comment starts with the disclaimer line and follows
[`../setup-tone/github-text.md`](../setup-tone/github-text.md). Write it to a
file in your scratchpad, and post it with the **Comment** operation.

## Triage notes for `needs-info`

```markdown
> *This was generated by AI during triage.*

## Summary

- Triage notes. This issue waits on @<reporter>.
- <What triage found so far, in one line.>

## Settled so far

- <a fact or decision from steps 3 to 6>

## Questions for @<reporter>

- <a question the reporter can answer in one line>
```

Put everything the grill settled under **Settled so far**, so the next session
does not ask it again. Each question names the exact thing missing, such as
the version, the command run, or the expected output.

## Resuming

When an issue has triage notes, read the replies after them. Before step 4,
show the user which questions are now answered and which are still open.

## Closing as `wontfix`

The closing comment depends on the reason. Use this shape for all three:

```markdown
> *This was generated by AI during triage.*

## Summary

- Closed: <already built | not a bug | will not fix | out of scope>.
- <The reason, or where the behavior lives, in one line.>

## Details

- <The command, type, glossary term, decision record or earlier issue.>
```

**Already built.** Name where the behavior lives: the command, the type, the
glossary term. Record nothing else. A built feature is not a rejection. A
record of it makes later duplicate checks report false rejections.

**Rejected bug.** Say why it is not a bug, or why it will not be fixed. Name
the decision record or constraint when one exists.

**Rejected enhancement.** Give a reason that lasts: the project's scope, a
technical constraint, or a decision already taken.

- "Not now" is a deferral, not a rejection. Leave such an issue open in
  `needs-triage` or `ready-for-human`.
- When the rejection passes the three tests in `h2xd:docs-adr` step 1, offer a
  decision record. Its overlap check finds the rejection the next time someone
  asks.
- Link the record from the comment.

## A request that matches a prior rejection

When step 3 finds a decision record or a closed `wontfix` issue for the same
concept, show it in step 4: "We rejected this in #<n> because <reason>. Does
that still hold?" Match by concept, not by word. "Night theme" matches a
rejected "dark mode".

| The user says | Then |
|---|---|
| Still holds | Close as a rejected enhancement. Link the earlier issue or record |
| Reconsider | Triage as new. When a record exists, supersede it with `h2xd:docs-adr` |
| A different request | Triage as new. Mention the related issue in the comment |
